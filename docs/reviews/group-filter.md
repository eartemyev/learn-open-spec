Четыре проверяемых следствия СБ остаются истинными по проверенному коду:

1. Конфигурация остаётся в браузере. В `src` нет обращений к `fetch`, `XMLHttpRequest`, `navigator.sendBeacon`, `WebSocket`. Новый обработчик меняет только локальное состояние React, сетевых операций не добавляет. Импорт и экспорт используют прежние локальные механизмы. Сетевой журнал браузера в рамках этого ревью не снимался.
2. Импорт проверяется целиком. `parseConfigFile` проверяет структуру и ссылки до `replace` в `useSimulator`; ошибка не меняет конфигурацию и сохранённое значение. Новый параметризованный тест в `Permissions.test.tsx:264` включает ссылку на несуществующего пользователя, проверяет сообщение об ошибке, прежнее значение `localStorage`, неизменный экспорт всей конфигурации и наличие пяти разрешений.
3. Операции затрагивают только выбранные разрешения. Фильтр не вызывает выдачу, отзыв или сохранение; панель получает полную конфигурацию. Неизменённый `removePermission` создаёт новый список исключительно исключением заданного идентификатора. При отзыве `p3` остаются прежние записи `p1`, `p2`, `p4`, `p5`, а пользователи, группы и сервисы сохраняются через копирование остальных полей конфигурации.
4. Независимые источники сохраняются. Расчёт по-прежнему получает полную конфигурацию, отзыв удаляет только выбранную запись. Прежний тест «отзыв одного разрешения сохраняет независимый источник доступа» и доменный тест операции подтверждают сохранение доступа Анны после удаления `p1` с единственным источником `p2`, группой «Бухгалтерия». Новый тест `App.test.tsx:185` дополнительно проверяет прямой источник и другую группу при активном фильтре.

Архитектурные правила соблюдены. `App` вызывает существующий `checkAccess`; отбор участников не рассчитывает доступ. Единственным модулем расчёта остаётся `src/domain/access.ts`. Компоненты не читают хранилище и не импортируют домен. Типы `AccessSource` и `Config` импортируются через `../app`; новых общих типов нет.
