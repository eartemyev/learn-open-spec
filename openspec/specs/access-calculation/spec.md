# access-calculation Specification

## Purpose

Зафиксировать текущее поведение расчёта доступа сотрудника к сервису по `src/domain/model.ts`, `src/domain/access.ts` и `src/domain/access.test.ts`.

## Requirements

### Requirement: Запрос и результат расчёта

Функция `calculateAccess` SHALL принимать конфигурацию `Config` со списками пользователей, групп, сервисов и разрешений и запрос `AccessQuery` с `userId`, `serviceId` и моментом `at` типа `Date`. Результат SHALL содержать `granted` и массив `sources`. Значение `granted` SHALL быть `true` тогда и только тогда, когда существует хотя бы один источник доступа.

#### Scenario: Подходящие разрешения отсутствуют

- **GIVEN** у пользователя и его групп нет разрешений на запрошенный сервис
- **WHEN** выполняется расчёт доступа
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Прямые разрешения

Расчёт SHALL включать источник для каждого разрешения, у которого `serviceId` совпадает с запрошенным сервисом, `subject.type` равен `user`, а `subject.id` совпадает с `userId` запроса. Прямой источник SHALL иметь вид `{ kind: "direct", permissionId }`, где `permissionId` — идентификатор разрешения.

#### Scenario: Доступ по прямому разрешению

- **GIVEN** единственное подходящее разрешение `p1` выдано пользователю `boris` на сервис `ledger`
- **WHEN** рассчитывается доступ `boris` к `ledger`
- **THEN** результат равен `{ granted: true, sources: [{ kind: "direct", permissionId: "p1" }] }`

#### Scenario: Разрешение другого пользователя

- **GIVEN** единственное разрешение на сервис выдано другому пользователю
- **WHEN** рассчитывается доступ запрошенного пользователя к этому сервису
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Разрешения групп пользователя

Расчёт SHALL брать членство из `groupIds` пользователя, найденного в `config.users` по `userId`. Каждое разрешение на запрошенный сервис с `subject.type`, равным `group`, и `subject.id`, входящим в этот список, SHALL давать источник `{ kind: "group", permissionId, groupId }`, где `groupId` равен `subject.id` разрешения.

#### Scenario: Доступ через группу

- **GIVEN** пользователь `boris` состоит в группе `support`, которой выдано единственное подходящее разрешение `p3` на сервис `mail`
- **WHEN** рассчитывается доступ `boris` к `mail`
- **THEN** результат равен `{ granted: true, sources: [{ kind: "group", permissionId: "p3", groupId: "support" }] }`

#### Scenario: Разрешения нескольких групп

- **GIVEN** пользователь состоит в двух группах и каждой выдано разрешение на один и тот же сервис
- **WHEN** рассчитывается доступ пользователя к этому сервису
- **THEN** результат содержит источники обоих разрешений и `granted: true`

#### Scenario: Разрешение чужой группы

- **GIVEN** единственное разрешение на сервис выдано группе, в которой пользователь не состоит
- **WHEN** рассчитывается доступ пользователя к этому сервису
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Отбор разрешений по сервису

Расчёт SHALL учитывать только разрешения с `serviceId`, равным `serviceId` запроса, независимо от совпадения пользователя или его групп.

#### Scenario: Разрешения выданы на другой сервис

- **GIVEN** у пользователя и его групп есть разрешения только на другие сервисы
- **WHEN** рассчитывается доступ к запрошенному сервису
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Полнота и порядок источников

Расчёт SHALL возвращать все подходящие разрешения отдельными источниками без устранения повторов. Прямые источники SHALL предшествовать групповым. Внутри каждой категории источники SHALL следовать порядку соответствующих записей в `config.permissions`, независимо от порядка `groupIds` пользователя.

#### Scenario: Прямое и групповое разрешения действуют одновременно

- **GIVEN** пользователь `anna` состоит в группе `support`, а групповое разрешение `p3` на `mail` расположено в `config.permissions` раньше прямого разрешения `p4` для `anna` на `mail`
- **WHEN** рассчитывается доступ `anna` к `mail`
- **THEN** `sources` равен `[{ kind: "direct", permissionId: "p4" }, { kind: "group", permissionId: "p3", groupId: "support" }]`
- **AND** `granted` равен `true`

#### Scenario: Несколько разрешений одного вида

- **GIVEN** на сервис выданы два прямых разрешения пользователю и два разрешения его группам
- **WHEN** рассчитывается доступ пользователя к этому сервису
- **THEN** результат содержит четыре источника: сначала оба прямых в порядке разрешений, затем оба групповых в порядке разрешений

#### Scenario: После удаления одного разрешения остаётся независимый источник

- **GIVEN** доступ к сервису обеспечивают прямое и групповое разрешения
- **WHEN** расчёт вызывается с конфигурацией, из которой удалено только прямое разрешение
- **THEN** `granted` остаётся `true`, а `sources` содержит оставшийся групповой источник

### Requirement: Поведение при отсутствующих записях справочников

Расчёт SHALL сопоставлять идентификаторы без проверки целостности ссылок. При отсутствии пользователя в `config.users` расчёт SHALL использовать пустой список групп, но продолжать учитывать прямые разрешения с совпадающим `userId`. Наличие сервиса в `config.services` и группы в `config.groups` SHALL NOT быть условием учёта разрешения. Это поведение доменной функции при прямом вызове; проверка импортируемой конфигурации находится за пределами этой спецификации.

#### Scenario: Неизвестный пользователь без прямого разрешения

- **GIVEN** пользователя нет в `config.users` и прямых разрешений для запрошенного `userId` нет
- **WHEN** выполняется расчёт доступа
- **THEN** результат равен `{ granted: false, sources: [] }`, даже если существуют групповые разрешения

#### Scenario: Прямое разрешение неизвестного пользователя

- **GIVEN** пользователя нет в `config.users`, но существует прямое разрешение с запрошенным идентификатором пользователя на запрошенный сервис
- **WHEN** выполняется расчёт доступа
- **THEN** результат содержит это прямое разрешение и `granted: true`

#### Scenario: Сервис отсутствует в справочнике

- **GIVEN** сервиса нет в `config.services`, но существует подходящее прямое разрешение с запрошенным `serviceId`
- **WHEN** выполняется расчёт доступа
- **THEN** результат содержит прямой источник и `granted: true`

#### Scenario: Группа отсутствует в справочнике

- **GIVEN** `groupIds` пользователя содержит идентификатор, которого нет в `config.groups`, и этой группе выдано разрешение на запрошенный сервис
- **WHEN** выполняется расчёт доступа
- **THEN** результат содержит групповой источник и `granted: true`

### Requirement: Независимость от времени и отсутствие побочных эффектов

Расчёт SHALL принимать момент `at` явно и SHALL NOT читать системные часы. В текущей модели разрешения не имеют срока действия, поэтому изменение только `at` SHALL сохранять результат. Функция SHALL выполнять расчёт без изменения конфигурации и запроса, без обращения к браузеру, хранилищу или сети.

#### Scenario: Разные моменты расчёта

- **GIVEN** одинаковая конфигурация, пользователь `boris` и сервис `ledger`
- **WHEN** расчёт выполняется с `at`, равным `2020-01-01T00:00:00Z`, и затем с `at`, равным `2040-01-01T00:00:00Z`
- **THEN** оба результата совпадают

#### Scenario: Повторный расчёт с теми же входными данными

- **GIVEN** конфигурация и запрос
- **WHEN** расчёт выполняется повторно с этими входными данными
- **THEN** результаты совпадают, а конфигурация и запрос остаются неизменными
