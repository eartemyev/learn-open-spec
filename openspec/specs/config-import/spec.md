# config-import Specification

## Purpose

Зафиксировать текущее поведение импорта конфигурации по `src/app/config-file.ts`, `src/app/storage.ts` и соседним тестам. Применение результата импорта описано по `src/app/index.ts`. Спецификация охватывает разбор JSON, проверку данных, замену конфигурации и хранение в браузере.

## Requirements

### Requirement: Разбор JSON и результат проверки

Функция `parseConfigFile` SHALL принимать текст JSON и возвращать либо `{ ok: true, config }`, либо `{ ok: false, errors }`, где `errors` — массив строк с причинами отказа. Корень JSON SHALL быть объектом, отличным от `null` и массива. Разбор SHALL выполняться без изменения текущей конфигурации, без записи в хранилище и без сетевых запросов.

#### Scenario: Некорректный JSON

- **WHEN** передан текст `{oops`
- **THEN** результат равен `{ ok: false, errors: ["Файл не разбирается как JSON"] }`

#### Scenario: Корень не является объектом конфигурации

- **WHEN** передан JSON с корнем `null`, массивом или примитивным значением
- **THEN** результат содержит единственную ошибку `Файл должен содержать объект конфигурации`

### Requirement: Версия формата

Файл SHALL содержать числовое целочисленное поле `version`. Поддерживаемая версия `CONFIG_VERSION` SHALL равняться `1`. Значение больше `1` SHALL приводить к отказу. Любое целое значение не больше `1`, включая `0` и отрицательные числа, SHALL допускаться к дальнейшей проверке по текущей структуре без миграции. Поле `version` SHALL NOT входить в возвращаемую `Config`.

#### Scenario: Версия отсутствует или имеет неверный тип

- **WHEN** `version` отсутствует, равна строке `"1"` или дробному числу
- **THEN** результат содержит единственную ошибку `Нет поля version с целым числом`

#### Scenario: Более новая версия

- **WHEN** `version` равна `2`
- **THEN** результат содержит единственную ошибку `Версия формата 2 новее поддерживаемой 1`

#### Scenario: Более ранняя версия

- **GIVEN** структура и ссылки конфигурации корректны
- **WHEN** файл содержит `version: 0` или `version: -1`
- **THEN** разбор завершается успешно по тем же правилам, что и для версии `1`

### Requirement: Обязательные списки и поля записей

Файл SHALL содержать массивы `users`, `groups`, `services` и `permissions`. Каждый элемент массива SHALL быть объектом. Пользователь SHALL содержать `id`, `name` и массив `groupIds`. Группа и сервис SHALL содержать `id` и `name`. Разрешение SHALL содержать `id`, `serviceId` и объект `subject` с полями `type` и `id`; `subject.type` SHALL равняться `user` или `group`.

Поля `id`, `name`, `serviceId`, `subject.id` и каждый элемент `groupIds` SHALL быть непустыми строками. Пробелы SHALL сохраняться без обрезки; строка из пробелов SHALL считаться непустой. Все четыре массива SHALL допускать пустое содержимое.

#### Scenario: Пустая конфигурация

- **WHEN** файл содержит `version: 1` и четыре пустых массива
- **THEN** результат равен `{ ok: true, config: { users: [], groups: [], services: [], permissions: [] } }`

#### Scenario: Обязательный список отсутствует

- **WHEN** поле `groups` отсутствует или не является массивом
- **THEN** список ошибок содержит `Поле groups должно быть списком`

#### Scenario: Элемент списка не является объектом

- **WHEN** `users[0]` равен `null`, массиву или примитивному значению
- **THEN** список ошибок содержит `users[0]: запись должна быть объектом`

#### Scenario: Неверное строковое поле

- **WHEN** `users[1].name` равно `5`, пустой строке или отсутствует
- **THEN** список ошибок содержит `users[1]: поле name должно быть непустой строкой`

#### Scenario: Неверный список групп пользователя

- **WHEN** `users[0].groupIds` отсутствует, не является массивом или содержит элемент, отличный от непустой строки
- **THEN** список ошибок содержит `users[0]: поле groupIds должно быть списком строк`

#### Scenario: Неверная форма субъекта разрешения

- **WHEN** `permissions[0].subject` отсутствует или не является объектом
- **THEN** список ошибок содержит `permissions[0]: поле subject должно быть объектом`

#### Scenario: Неизвестный тип субъекта

- **WHEN** `permissions[0].subject.type` равен `team`
- **THEN** список ошибок содержит `permissions[0]: тип субъекта должен быть user или group`

### Requirement: Уникальность идентификаторов

Идентификаторы SHALL быть уникальны внутри каждого из четырёх списков. Одинаковые идентификаторы в разных списках SHALL допускаться. Проверка SHALL NOT запрещать разные разрешения с одинаковыми субъектом и сервисом или повторяющиеся элементы `groupIds`, если остальные требования выполнены.

#### Scenario: Повтор идентификатора сервиса

- **GIVEN** `services[0].id` равен `ledger`
- **WHEN** `services[1].id` также равен `ledger`
- **THEN** список ошибок содержит `services[1]: идентификатор «ledger» уже занят`

#### Scenario: Совпадение идентификаторов между списками

- **GIVEN** пользователь и группа имеют одинаковый `id`, а все ссылки корректны
- **WHEN** файл проверяется
- **THEN** совпадение между списками не препятствует успешному разбору

### Requirement: Ссылочная целостность

После успешной проверки структуры разбор SHALL проверять ссылки только на записи импортируемого файла. Каждый `groupIds` пользователя SHALL ссылаться на существующую группу. Субъект разрешения SHALL ссылаться на существующего пользователя при типе `user` или группу при типе `group`. Каждый `serviceId` разрешения SHALL ссылаться на существующий сервис.

#### Scenario: Пользователь ссылается на отсутствующую группу

- **WHEN** `users[0].groupIds` содержит `ghosts`, которого нет среди групп файла
- **THEN** список ошибок содержит `users[0]: нет группы «ghosts»`

#### Scenario: Разрешение ссылается на отсутствующего пользователя

- **WHEN** `permissions[0].subject` равен `{ type: "user", id: "nobody" }`, а такого пользователя в файле нет
- **THEN** список ошибок содержит `permissions[0]: нет пользователя «nobody»`

#### Scenario: Разрешение ссылается на отсутствующую группу

- **WHEN** `permissions[1].subject` равен `{ type: "group", id: "ghosts" }`, а такой группы в файле нет
- **THEN** список ошибок содержит `permissions[1]: нет группы «ghosts»`

#### Scenario: Разрешение ссылается на отсутствующий сервис

- **WHEN** `permissions[2].serviceId` равен `vault`, а такого сервиса в файле нет
- **THEN** список ошибок содержит `permissions[2]: нет сервиса «vault»`

### Requirement: Этапы проверки и сообщения об ошибках

Ошибки синтаксиса JSON, корневого значения и версии SHALL завершать проверку сразу. После этих проверок разбор SHALL обходить все четыре списка в порядке `users`, `groups`, `services`, `permissions` и накапливать ошибки структуры, полей и повторов идентификаторов. При наличии таких ошибок проверка ссылок SHALL NOT выполняться. При корректной структуре разбор SHALL накапливать все ошибки ссылок: сначала членство пользователей в группах, затем ссылки разрешений. Сообщения об ошибках записей SHALL указывать имя списка и индекс записи в исходном файле, начиная с нуля.

#### Scenario: Несколько ошибок ссылок

- **GIVEN** структура файла корректна
- **WHEN** `permissions[0].serviceId` указывает на отсутствующий `vault`, а `permissions[1].subject.id` — на отсутствующую группу `ghosts`
- **THEN** результат содержит обе ошибки в порядке записей разрешений

#### Scenario: Ошибка структуры предшествует проверке ссылок

- **GIVEN** `users[1].name` равен `5`, а разрешение ссылается на отсутствующий сервис
- **WHEN** файл проверяется
- **THEN** результат содержит ошибку поля `users[1].name`, а ошибка ссылки на сервис не добавляется

### Requirement: Неизвестные поля и совместимость с экспортом

Разбор SHALL игнорировать неизвестные поля на уровне корня, записей и `subject` и SHALL возвращать конфигурацию только с известными полями, сохраняя порядок записей и элементов `groupIds`. Функция `exportConfig` SHALL выдавать JSON с `version: 1` и данными конфигурации, с отступом в два пробела. Экспорт корректной `Config` и последующий разбор SHALL возвращать равную ей конфигурацию.

#### Scenario: Дополнительные поля

- **GIVEN** корректный файл содержит `exportedBy` в корне, `nickname` у пользователя и дополнительное поле в `subject`
- **WHEN** файл разбирается
- **THEN** разбор успешен, а дополнительные поля отсутствуют в возвращённой конфигурации

#### Scenario: Экспорт и повторный импорт

- **WHEN** выполняется `parseConfigFile(exportConfig(seedConfig))`
- **THEN** результат равен `{ ok: true, config: seedConfig }`

### Requirement: Применение импорта целиком

Операция `importJson` SHALL сначала проверять весь текст через `parseConfigFile`. При отказе она SHALL возвращать ошибки без изменения текущей конфигурации и сохранённой копии. При успехе она SHALL полностью заменять текущую конфигурацию результатом разбора, вызывать её сохранение и возвращать `{ ok: true }`.

#### Scenario: Ошибочный файл не применяется частично

- **GIVEN** текущая конфигурация и её сохранённая копия существуют
- **WHEN** импортируется файл с корректными записями и хотя бы одной ошибочной ссылкой
- **THEN** операция возвращает ошибки, а текущая конфигурация и значение в хранилище остаются прежними

#### Scenario: Успешный импорт заменяет конфигурацию

- **GIVEN** текущая конфигурация содержит записи, отсутствующие в корректном импортируемом файле
- **WHEN** выполняется импорт этого файла
- **THEN** текущая конфигурация равна конфигурации файла без объединения с прежними записями
- **AND** вызывается сохранение новой конфигурации и возвращается `{ ok: true }`

### Requirement: Загрузка и сохранение в браузере

Функция `saveConfig` SHALL записывать результат `exportConfig` по ключу `access-policy-simulator:config` в переданное хранилище `Storage`. Функция `loadConfig` SHALL читать этот ключ и проверять сохранённый текст через `parseConfigFile`. При отсутствии значения, любой ошибке проверки или исключении при чтении она SHALL возвращать `seedConfig`. Загрузка SHALL NOT записывать или удалять данные хранилища. Ошибки сохранения SHALL подавляться; операция импорта SHALL сохранять новую конфигурацию в текущей вкладке и возвращать успех даже при неудачной записи.

#### Scenario: Чтение сохранённой конфигурации

- **GIVEN** `saveConfig` успешно сохранила корректную изменённую конфигурацию
- **WHEN** вызывается `loadConfig` с тем же хранилищем
- **THEN** возвращается сохранённая конфигурация
- **AND** сохранённый текст совпадает с результатом её экспорта

#### Scenario: Учебные данные при отсутствии или непригодности сохранённой копии

- **WHEN** значение отсутствует, содержит повреждённый JSON, неподдерживаемую версию или нарушенные ссылки, либо чтение вызывает исключение
- **THEN** `loadConfig` возвращает `seedConfig`, а содержимое хранилища не изменяется

#### Scenario: Хранилище недоступно для записи

- **GIVEN** запись в хранилище вызывает исключение
- **WHEN** импортируется корректный файл
- **THEN** текущая конфигурация заменяется импортированной, операция возвращает `{ ok: true }`, а исключение записи не передаётся вызывающему коду
